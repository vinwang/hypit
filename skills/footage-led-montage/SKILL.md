# 素材驱动混剪标准

当用户提供视频素材并要求制作、重剪、混剪、宣传、商品展示、短视频或广告片时使用本 Skill。源素材必须是成片画面的主要依据；文字、声音和图形只负责解释、强调和促进行动。本 Skill 不用于没有源素材的纯文字生视频、长篇纪录片拼接、主要解决对白清理的访谈剪辑或单纯转码。生成镜头路线（Kling 等）不属于本 Skill 的 runner，但其成片仍按本文件的验收门槛交付。

本文件是生产合同，不是口头承诺。只有当渲染参数、时间线清单和逐项 QA 证据都能证明规则已执行时，输出才可标记为 `pass`；渲染器不支持某项规则或无法提供证据时，必须标记 `revise`/`blocked`。

## 配方是唯一配置来源

一次复刻的生产参数全部写进 `projects/<project>/recipe.json`，由 `skills/footage-led-montage/recipe.schema.json` 校验。配方与选段计划的分工是固定的：

- **配方**（`recipe.json`）：身份与锁定（`id`/`supersedes`/`runner_sha256`/`fixed_visual_profile_id`/`locked_assets_id`）、`canvas`、`timeline`（`body_frames`/`tail_frames`/`crossfade_frames`）、`categories`（`product_category`/`source_categories`/`excluded_categories`/`asset_category`）、`asset_roots`、`locked`（`narration`/`music_bed`/`tail`/`graphics`，逐项带 `sha256`）、`audio_mix`、`batch`（`variant_count`/`shots_per_variant`/`duplicate_policy`）、`snapshot_prefix`、`manifest_record`、`output_naming`、`paths`、`decision_log`。**这些值不随批次变化。**
- **选段计划**（`paths.plan` 指向的 batch plan）：每条变体用哪些源镜头、每个镜头的源区间与裁切。**批次之间只改这里。**

规则、QA 和报告只能引用配方，不得在下游复制一份不同的值。参考视频、模板、渲染器默认值、字体回退、平台预设和自动素材选择都不能覆盖配方。

- **双锁**：`recipe.runner_sha256` 锁定允许执行它的 runner，哈希不符时 runner 直接拒绝运行；每次运行再把 `recipe_sha256` 与 `runner_sha256` 一起记进 `paths.reports` 下的计时报告。`runner_sha256` 为 `null` 表示锁尚未建立。
- **共享音频清单锁**：`manifest_record.shared_audio_key` 是共享资产清单里锁定混音的条目名 —— 该条目已存在且哈希不同时 runner 拒绝运行。`manifest_record` 的其余字段（`variant_set_suffix`/`source_material_rule`）只做记账，不影响任何一帧。
- **路径与身份**：锁定资产以「规范化路径 + SHA-256」确认身份，外部路径只能作为导入源。哈希不符、路径失效或资产缺失时必须 `blocked`，不得静默替换、移动、缩放或降级。
- **两级品类不得混用**：视频按细分的素材品类进入 `asset_roots.source_root/<product_category>/`，BGM 与配音按资产大类共用；`asset_category` 只由配方显式登记，不得从商品名推断、不得跨大类借用、也不得作为放宽视频品类范围的理由。新增素材品类必须在同一次变更中登记。
- **唯一变更入口**：只有用户明确修改固定项，才可创建新的配方版本；必须递增 `id`/`supersedes` 并在 `decision_log` 追加同一 subject 的修订记录，同时使旧时间线、渲染报告和 QA 全部失效。项目自带的 `AGENTS.md` 若与本文件或配方冲突，以配方为准并标记 `blocked`，不得自行取舍。
- **图形层是锁定资产，不是重建项**：参考片的促销卡、CTA、说明、水印由 `tools/graphics/extract-overlay.py` 从参考片帧整层抠出，作为 alpha overlay 复用（`locked.graphics`）。不得改用重建字体的做法；哪几层文字存在由配方与已批准的图形层决定，本文件不规定字体、字号或描边。

## 执行顺序

1. 读取用户简报、平台版位与源素材，先确认 `product_category`，再由配方解析 `asset_category`，锁定 `locked` 下的全部资产路径与哈希。
2. 记录每个源文件的时长、画幅、帧率、音频、内嵌字幕、真实场景切点和可用连续动作（`hypit media boundaries` 给机械切点候选，人工复核）。
3. 生成或导入文案后，先让用户确认事实和表达；未确认的文案不能进入最终配音。
4. 用户提供的音频若被说明为音色参考，只用于提炼音色、语速、语气、停顿和情绪特征；必须用匹配的 TTS/voice-clone 路径重新合成已确认文案，不得直接使用其原文、整段截取、拼接或把转录内容当作本项目文案。只有用户明确要求同一人声克隆时才强制 voice clone。
5. 以最终配音的实际时长和词级/句级时间戳建立时间线；脚本字数不能代替音频时长。
6. 按音频时间线设计镜头，选段写入 batch plan；渲染、抽帧、验收按本文件规则执行。
7. 每个变体都要生成可追溯的时间线和 QA 记录；任一必检项失败、未验证或配置缺失，都不得标为最终成片。

## 批量效率与返工控制（必需）

以下步骤用于减少重复扫描和整批返工，不得降低本 Skill 已规定的素材、画面、音频、重复度或逐条 QA 门槛：

1. **一次扫描并缓存**：素材盘点、元数据、哈希、场景切点和候选区间结果按源文件 SHA-256 缓存；文件和检测参数未变时复用结果，不得因局部修改重扫整个素材库。粗筛可用低分辨率代理，最终候选仍须检查实际区间。
2. **渲染前锁定全部镜头**：一次完成所有变体的选段、品类/相关性/黑名单/源字幕检查与重复度比较。镜头不合格时先替换并更新受影响的比较结果，不得先渲染整批再开始筛查主体画面。
3. **先验收一条完整成片**：先锁最终配音和实际时间线，再制作一条端到端样片；按最终文件证据验收通过后锁定公共配置，再渲染其余变体。样片计入交付数量。
4. **按影响范围返工**：缓存键至少包含源 SHA-256、源入出点、裁切/转场参数、配方 ID 和叠加资产哈希。仅单条变体变化时只重渲该变体，并重做因此失效的 QA 与重复度比较；配方、公共音频或尾板变化时重渲所有受影响变体。runner 以哈希判断复用，任何输入变化都会让对应缓存失效 —— 但**任何输入变化后都必须重跑 QA**，不得沿用旧报告。
5. **分阶段计时与复盘**：从批次开始到交付记录端到端起止时间；在 `paths.reports` 为项目预检、素材筛选/人工复核、剪辑计划、配音/音乐、代理/图层、样片、批量渲染、最终 QA、返工复验和发布分别记录起止时间、墙钟耗时、可测的主动处理时间、人工复核时间、外部/API 等待时间、状态和产出。未实测字段写 `unknown`，不得倒推或估填；并行阶段注明耗时不可相加。报告末尾指出最长的已测阶段及一项对应提速措施。渲染失败时停止后续批量工作，只重跑受影响项目；大范围返工或预计耗时显著变化时告知用户。

## 文案、配音与时间线锁定顺序

严格执行以下不可逆顺序：

1. **文案确认**：确认最终文本、价格写法、CTA、法律说明和需要去除的标点；未确认内容只能标记为草稿。
2. **配音锁定**：记录参考音频和最终音频的规范化路径、SHA-256、音频时长、词级/句级时间戳和转录文本；锁定后不得重新生成、换声音、改语速或剪改停顿。
3. **时间线建立**：依据实际音频时间戳安排镜头与价格强调点；镜头边界可以落在 3 秒节拍之外，但必须记录理由。
4. **音频变更失效**：用户明确批准配音文本、语速、停顿、采样率或文件变化后，旧镜头时间线、字幕时间和成片 QA 全部作废，必须重新建立。
5. **成片验收**：最终编码文件的旁白、字幕、价格和画面动作必须与实际音频对齐；没有最终音频不能生成"最终版"。

## 规则1：混剪与镜头节奏

- 3 秒是主镜头的默认最小时长和规划网格，不是强制把每句话切成 3 秒。音频语义边界落在镜头中间时保持当前连续镜头，不得为了对齐每句旁白额外切画面。
- 普通主镜头输出时长不得短于 3 秒；完整动作可以长于 3 秒。只有最终剩余时长不足 3 秒时，才允许将尾镜头并入前镜头，或作为有明确语义落点的最后一段保留并记录理由。
- 使用 12 帧转场时，源片段长度应为该镜头输出时长加 0.4 秒转场手柄。只有恰好 3 秒的镜头对应 90 帧输出和 102 帧源片段，不能把该数值套用到所有镜头。
- 第一镜头不需要入场手柄；最后镜头仅在确实转入已提供的尾部视频时需要出场手柄。尾部视频只是预留状态时，不得为不存在的转场增加空帧。
- 输出源画面只在时间线清单中的计划边界切换；每个边界必须来自 3 秒节拍、完整动作结束或已记录的音频语义理由。
- 不得通过加速、重复、冻结或无依据快切填充时长；任何短于 3 秒的非尾部镜头都直接判定为失败，除非用户明确批准该切点。
- 外层 3 秒片段内部不得再出现约 1 秒一次的源视频快切；候选源区间必须做场景检测和人工抽帧检查。
- 被描述为连续动作的源区间，内部硬切数量必须为 0；建议 scene threshold 0.3，并人工复核疑似漏检的切点。
- 内部硬切检测必须**排除每段自身的入场叠化窗口**与下一段的出场重叠段：叠化期间的帧间差是一条先升后降的平滑驼峰，对静止镜头其峰值可达中位差的 3-5 倍，会被"diff>15 且 ≥3× 邻域中位数"的单帧尖峰判据误报成隐藏硬切。真实硬切的特征是"单帧尖峰 + 前后立刻回落到本底"，与平滑驼峰必须区分；被排除的窗口要在 QA 证据里逐帧列出，不得静默丢弃。
- **硬切切点必须记为区间而非时刻**（一处硬切常连续 2~5 帧超阈，只记一个时刻会让切变帧留在片段内）；任何"帧下标 × 时间阈值"的比较都必须显式换算帧号与秒 —— 曾出现把帧号当秒比较，导致大时间戳的窗口整段跳过硬切检测。
- 跨不同源文件或不同构图的边界不得默认使用裸硬切：必须证明主体动作、镜头方向、景别和明暗连续，或使用 12 帧覆盖叠化；如果当前渲染器不能提供真实重叠过渡，就必须改用连续源区间或标记 `blocked`，不得用 `transition_in: cut` 掩盖视觉跳变。
- 不得重复已完整出现的动作或画面；相邻片段最多共享转场短手柄，不得造成重复观看感。
- 删除无关空镜、无动作停留、失焦、严重曝光和无法支撑旁白的素材。
- 镜头逻辑按"吸引点击→展示主体→细节证据→过程或口感→完整商品→行动引导"推进。
- 源素材不足以支撑某卖点时，暴露缺口并调整文案或方案，不能用无关画面伪造证据。

## 规则2：画面切换与转场

- 默认转场为 `timeline.crossfade_frames` 帧（配方值，30fps 下 12 帧即 0.4 秒）。
- 使用上一画面保持不透明、下一画面位于上层渐入的覆盖叠化。
- 12 帧叠化必须是真实时间线重叠：后一镜头的 `in_seconds` 至少提前 0.4 秒，前后源片段保留足够 handle；只设置 fade 字段但让两个 Sequence 首尾相接不算叠化。
- 禁止两层同时降低透明度，禁止淡黑、黑场、闪黑、闪白、亮度骤降、解码空帧和单帧断裂。
- 转场曲线使用平滑缓入缓出，不使用旋转、闪烁、故障、缩放或装饰性转场填充时间。
- 只有同一动作/同一构图连续，或计划边界确有充分语义落点且人工抽帧证明无突兀跳变时才允许硬切；不同源文件的视觉跳变不能仅凭"计划边界"通过。
- 每个边界抽查转场前、边界时刻、转场中点和结束后的画面。

## 规则3：源素材文字清理

> **2026-09-22 用户明确批准修订本规则。** 原条款禁止一切遮罩，严格照做只有「全窗无字」的长段可用 —— 实测 3.0 秒口径下两库合格长段 519 段中，全窗无字仅 188 段，另有 55 段部分有字、**276 段全窗有字**（比无字段还多），即去字是产能杠杆而非锦上添花。修订后**受限允许 delogo 遮罩**，但遮罩必须满足下面的整行覆盖要求并通过像素级字形门。本修订不改动任何固定视觉项。

- 源视频中的白色字幕、营销文案、贴纸、水印和不需要的 Logo 必须清除、避开或裁切。
- 清理路径按优先级执行：
  1. **优先改用无内嵌文字的源素材区间**（已批准配方采用的做法：直接替换带字镜头）。
  2. **次选 delogo 遮罩**：允许保留带字幕镜头，但遮罩必须遮掉**整行文字**，不得只遮住 OCR 检出的部分字块 —— 只盖中段会让首尾字露出（用户投诉的「粒…味」即此类），遮罩必须覆盖该文字行的完整外接矩形。整行延伸三条件必须**同时**成立：① 纵向与锚定行重叠 ≥60% 字高；② 字块高度在锚定高度的 0.5~2.0 倍（字号一致）；③ 水平间隙 ≤44px。**只延伸面积 ≤6% 画面的「字幕级」遮罩** —— 大遮罩本身是包装印刷块，延伸只会把整箱产品糊掉（实测 27%→58%）。新增遮罩须落在标题带（`y<0.22`）或字幕带（`y 0.66~0.92`），或为 ≥4 汉字的成句文字；且必须**时域稳定**（多帧读到同一串文字才算真烧录字，纹理误读逐帧都变；实测该闸把新增窗口从 17 降到 9），标题/字幕带内 ≥4 汉字即使只命 1 帧也认。遮罩面积按**并集**计（重叠遮罩逐块相加会虚高）。
  3. 前两条都不可行时，只允许在不损坏主体和构图的情况下裁掉字幕边缘。
- **遮罩覆盖必须用像素级字形门复核，不得只用 OCR 复扫**：残留只剩 1~2 个字时 OCR 置信度不足读不出，遮罩把字糊成半透明后更读不出 —— 「无 OCR 命中」不等于「没有字」。判据是扫**源素材帧**的字形（白字身 + 黑描边）是否被遮罩矩形完全包住，对**成片实际使用的切片**（`paths.manifest`，不是候选段池）全量核验，**暴露率必须为 0**。
- 判据的防假阳性要求（每条对应一次真实误报）：① 白字身必须是**纯白 `min(R,G,B) ≥ 235`**（只用「亮+低饱和」会把纸箱棱边、锡箔高光当字，实测该条把越界候选 8→1）；② 行带必须**逐遮罩**取，且只采纳纵向与该遮罩行真正相交的文字行；③ 行带取遮罩行 ±80px 并**丢弃触碰行带上下边界的连通域**（窄带裁切会把大片高光切成字形大小的碎片）；④ 字形尺寸须满足「宽 ≤2.5× 中位字宽、高 ≤1.8× 中位字高」；⑤ 越界量**不得**以「遮罩并集外包矩形」为基准（多遮罩窗口会横跨整画面，越界都算成 0），须逐点判定并报**暴露率**。
- **工具现状（必须如实记录）**：`tools/qa/mask-coverage.py` 是**图形层**（参考片 overlay）的像素门，不是源素材遮罩的门；仓库目前没有源素材遮罩的独立判据工具。共用的像素判据在 `tools/lib/glyphs.py`。因此凡是使用 delogo 遮罩的批次，必须自带等效的像素证据与 `--selftest` 式回归自检，否则该项标 `unverified` 并阻断通过。必须如实写明局限：只覆盖「白字身 + 黑描边」的烧录字，彩色字幕与不在遮罩行 ±80px 内的文字由成片侧残留扫描兜底。
- **不得用模糊块、黑条或遮罩外新增文字遮盖源字幕**；遮罩只允许覆盖已识别的源文字行本身。
- 标准化后抽查片段开头、中间和结尾，确认源字幕没有残留。
- **成片残留扫描必须排除锁定尾部**：尾部是平台固定素材，其自带画面文字属设计内容而非源字幕残留；不按尾部区间排除会产生大量假命中（实测 20 条各报 100+ 条）。
- 包装或道具上的真实印刷文字可以保留，但不能与新增文案混淆或争夺视觉重点。

## 规则4：颜色

- 默认保留源素材原色，不额外提亮、加黄、加暖、过度提高饱和度或对比度。
- 玉米、食品或农产品保持自然质感，避免发灰、泛黄、过曝、失去高光细节或片段间颜色跳变。
- 只有存在明显曝光、白平衡或色彩差异时才做必要的一致性校正，并在编辑决策记录。
- 最终编码帧不得出现 Vignette、radial-gradient 边缘压暗或任何等效暗角；首帧、中段、末帧至少各抽查一次，发现边缘黑化直接判定 `blocked`。
- **像素格式必须由渲染参数显式保证**：H.264 编码器在未显式指定时可能输出 full-range 的 `yuvj420p`，不满足本 Skill 的 `yuv420p` 要求。`ffprobe` 报出 `yuvj420p` 或 `color_range=pc` 时判定 `fail`，必须修正渲染参数后重新渲染，不得用后处理转码掩盖，也不得改写门槛去迁就渲染器默认值。

## 规则5：文案与投流合规

- 旁白和屏幕文字简短、口语化、生活化，不使用播音腔或空泛广告套话；前几秒先给出产品、动作、结果或视觉冲击点，建立观看理由。
- 每句旁白必须能在当前画面中找到动作、产品细节或可见证据。删除多余空镜、重复口号和与画面无关的旁白。
- 不得编造价格、折扣、产地、库存、物流、功效、新鲜度或绝对化承诺。
- 产品名、价格、CTA 和法律文案以用户简报为准；法律文案逐字保留。未特别定义时使用已批准配方/图形层中的文本，不得改写、删字、增字、替换同义词或调整标点。
- 文案包含价格时，按适用平台规则确认是否需要"起"；"X元起"必须在画面、旁白和字幕中保持金额与"起"字一致，不得自行改成更低价格或把"起"漏掉。
- 投流文案、画面、字幕、旁白、贴纸、封面和其他版位不得出现箭头、指向性手势或明显指向符号，大面积模糊/蒙版，人物纹身、脸部遮挡、豆包脸或明显面部生成伪影，大片红色、五角星、国旗、国家代表人物或其他国家相关元素，粉丝数达到或超过 50 万的网红、主持人或其他知名人物，未经证实的价格比较、"一杯奶茶钱/一顿饭钱"等表达，以及数字 `8.9`、`6.4`、`8.8`；"省钱"不得扩写成未经证实的省钱金额。任一版位的禁用项也适用于同一素材包的其他版位。
- 投流素材先筛查画面，再检查字幕、旁白、标题、CTA 和说明文案；脸部、品牌、数字或国家元素无法确认时剔除对应源区间。价格、优惠和资格信息必须有用户或项目证据，不得把参考视频或规则示例当作商品事实。
- CTA、说明文案和品牌水印按已批准配方与图形层全程存在（首帧到末帧，含尾部）；尾部不得显示顶部商品名/价格。投流素材的三要素缺失或原文不一致即阻断交付。
- 结尾保留明确行动引导，但不得加入用户未确认的额外承诺。
- 中文旁白不能用只支持拉丁词元的转录比对器作为唯一证据。应使用 TTS 服务返回的原文、句级/字级时间戳和中文字符级比对；工具不支持中文时必须在 QA 中写明限制，不得把空 token 结果当成通过。
- 参考视频只用于镜头内容、节奏、源文字清理和固定文字框的视觉核对，不得覆盖配方中的任何固定视觉字段；参考视频中的价格、品牌、单位、数量不得当作本项目事实。
- 用户已经明确确认的文案、CTA、说明文案、水印归属、平台规格和"尾部仅预留"等规则不得重复询问；只有缺少会影响交付的素材路径、最终配音、尾部资产、水印归属或平台规格时才暂停。

### 条件品类合规检查

仅当项目简报明确属于对应品类时执行以下清单；其他品类不得误套。

**捡漏**

- 封面不出现品牌标签、人民币或其他国家货币、虚构人物身份、狰狞表情、暴露衣着、坦克、警车或警察。
- 字幕不出现"限期、限时、最、天花板、百分数、国外"。
- 不出现麻将桌、电动车或电器，包括电锅、电饼铛和洗衣机；单价低于 5 元的商品不出现。

**美妆**

- 产品必须有项目可核验资质；封面不带大牌 Logo 或 App Logo。
- 不出现政治、军事、国家相关元素或粉丝数达到或超过 50 万的网红。
- 按项目审核要求检查价格弹窗"商品二折以上"，不得自行改变价格。
- 不出现"卷""彩票""天菜""天花板"；封面不写"进群薅小样"，不写未经资质证明的功效词，包括抗老、抗皱和美白。

**图书**

- 不出现纹身、警车、警察、交警、警犬、坦克、质检报告或无法核验的证明画面；严格检查音画同步。
- 不出现"撕不烂咬不破""越来越…""提高大脑认知""恒源祥""好几百箱""我已经领了几百本了""扬子鳄""金龟子""没有那个小孩能拒绝""90%""土豆埋在地里""仅几十套""聪明的大脑""书店不能上架""专注力""卖不出去""比某某好玩一百倍""库存马上就没了""幼小衔接""限时""鞭炮""天花板""最优""专治""你永远也考不过…的人"等表达。
- 不出现警车绘本、警察绘本和军事绘本。

## 规则6：旁白、BGM 与音效

- 用户指定最终配音路径时，直接锁定该文件，不得再调用 TTS、换声音、改语速、删停顿或替换文件。未指定配音文件时，才可按已批准的声音路径生成；生成结果经确认后立即锁定为 `locked.narration`。
- 配音锁定前可以修正无意义长气口；锁定后不得剪改。发现吞字、异常停顿或质量问题时标记 `blocked`，由用户确认是否产生新的配音资产版本。
- 用户指定 BGM 路径时，直接锁定该曲目，不得搜索、生成或替换音乐。允许为成片时长做裁切、淡入淡出、音量调整和人声 ducking，但衍生文件必须记录锁定源文件路径与哈希。
- 人声始终为主声道；BGM 低于人声，并在人声出现时自动 ducking。混音增益与限制器只读 `audio_mix`。
- 价格或优惠强调点可使用短促提示音，但只能在批准时间点少量出现。
- 检查人声、BGM、音效是否来自锁定资产、同步、清晰、无削波、无意外静音和突然音量跳变；响度以项目或平台目标为准。
- 人声、字幕、价格和 CTA 必须音画同步；人物口型与旁白不一致、价格或 CTA 与声音错位时判定失败。
- 尾部音频按 `locked.tail.audio_interval_seconds` 取锁定片段，不得改用尾板视频的原生音轨（除非配方如此声明）。

## 规则7：成片规格与验收

- 成片时长由最终配音实际结束时间、固定尾部视频真实时长和已确认的拼接方式共同决定；尾部资产不得丢弃或缩短。只有用户明确批准"尾部仅预留"时才可不拼接，并必须在交付配置和 QA 中记录该例外。
- 不得为了达到预设秒数复制画面、冻结画面、加速切镜或无依据延长静音。
- 最终画布严格按 `canvas` 输出，不得根据素材、参考视频或平台预设切换尺寸。改变画布须由用户明确提出并按"唯一变更入口"修订。
- 输出使用 H.264、yuv420p、AAC 和 faststart；必须同时包含视频流和音频流。
- 腾讯广告、微信视频号信息流或朋友圈投流时，视频画布遵循配方；平台要求不同画布时标记 `blocked`，不得自动导出第二种尺寸。本 Skill 不输出横屏视频。封面图或组图属于独立静态资产，不改变视频输出画布：横图 1280×720、竖图 1080×1920、1:1 组图 800×800，格式仅限 JPG/JPEG/PNG，单张小于 400KB。
- 同时要求视频号信息流和朋友圈时，规格相同且用户未要求分文件，则每个变体只输出一个共享视频，在 `platform_exports` 中记录两个 `platform_targets` 和同一个输出路径，并用一次 `ffprobe` 验证。
- 首次导出文件名采用"年份+日期+版位或共享版位标识+商品缩写+序号"；版位、日期和缩写必须来自项目配置或用户指定，版本号必须与导出记录一致，不得复制示例名。

针对最终编码文件逐项检查：

1. **批量**：输出变体数量严格等于 `batch.variant_count`，每条变体有独立文件和 QA 记录，不能只是复制改名；重复比例按 `duplicate_policy` 验收。
2. **容器**：画布与 `canvas` 完全一致；帧数等于 `timeline.body_frames + timeline.tail_frames`；帧率、H.264/AAC 音视频流、像素格式和 faststart 正确。
3. **镜头**：标准化片段符合编辑方案主时长；连续动作片段内部没有隐藏硬切。
4. **时间线**：源素材只在计划边界变化，没有空隙、重复片段或 1 秒级源快切。
5. **转场**：边界前、中、后无黑影、黑帧、闪帧、亮度下降、解码空帧或冻结。
6. **源文字**：内嵌字幕、贴纸和不需要水印已清理或避开，裁切没有损伤主体；使用遮罩时按规则3提供像素级证据。
7. **图形层**：`locked.graphics` 的哈希与磁盘一致；图形层像素门的暴露率为 0；CTA、说明、水印按已批准图形层全程覆盖至尾部末帧。
8. **音频与资产**：`locked` 下全部资产的规范化路径及 SHA-256 一致；旁白、人声、音乐、尾部音轨和批准音效存在、同步、清晰，BGM 低于人声，无削波和意外静音。
9. **运动**：无跳帧、冻结帧、不自然变速、解码伪影和切点附近不稳定裁切。
10. **内容**：每个卖点有画面证据或用户批准，开头有吸引力，过程有推进，结尾有明确落点。
11. **投流合规**：按规则5逐项检查；共享版位输出符合平台规格。
12. **条件品类规则**：只有项目明确属于对应品类时，才执行其专属禁用清单。

任一必检项失败都必须报告失败位置和原因，修复源素材、编辑逻辑或合成参数后重新渲染。不得静默降级、替换无关素材或覆盖未经验证的最终输出。

## 批量重复度定义

两个口径必须**分别报告**，回答的是不同问题：

- **源复用（计划级）**：读 batch plan。对每一对变体比较源素材清单、源文件入出点和画面指纹；同一源区间或被指纹确认是同一完整动作的区间，按重叠秒数计为重复素材。`pairwise_duplicate_ratio = shared_duplicate_seconds / min(content_duration_a, content_duration_b)`，分母取两条变体主体内容时长中的较小值（保守口径）。runner 会在渲染前拒绝超限批次，`qa/verify.py` 再从计划复算一遍并与 runner 记录的值比对，防止渲染后被改计划。
  - **复用单位是「连续镜头段」，不是「窗口」。** 同一段连续镜头的两个不同子窗口（例如 9.0-13.2 与 10.5-14.7）本身就构成重叠，必须计为重复；不得因为 `in/out` 不完全相同就当成两个互不重复的素材。这与观众的实际感受一致 —— 「官方门全绿、用户仍然投诉重复」的根因就是按窗口口径计算。**同一连续镜头不得被任意两个镜头位使用（段级复用恒为 0），任意两条变体共享的连续段数恒为 0**；每条变体的各镜头必须来自不同源文件。
  - **源身份按「画面内容」而不是文件名判定**：素材库存在字节不同、但逐帧 `corr≈0.9997 / MSE≈1.1` 的同画面文件（重复上传）。指纹比对**不得使用 16×16 二值指纹 + 汉明距离** —— 它对同品类同机位画面没有区分度，会把「长得像但不同」的镜头误判为重复（实测相邻窗口二值指纹几乎一致，实际 corr 仅 0.84~0.96 / MSE≈900）。须用逐帧 `corr ≥ 0.99` **且** `MSE ≤ 50` 覆盖 ≥85% 帧判定「同一完整动作」。
- **画面重复（成片级）**：从交付文件本身测量，覆盖时间错位的重复（同一画面晚几秒出现也算）。只排除 `duplicate_policy.comparison_region` 之外的固定叠加层与尾部插槽。方法常量（采样率、指纹尺寸、汉明阈值、像素确认判据）是度量本身的一部分，**不可配置** —— 改一个数就改了结论。
- 同一源文件的不同、无重叠区间不算重复；无法建立源区间映射或无法完成指纹比对时，状态为 `unverified`，不得标记 `pass`。
- 任意一对变体超过 `duplicate_policy.max_pairwise_ratio` 即判定 `revise`；只有所有配对均符合阈值且有证据时才允许 `pass`。

## QA 证据合同

每个变体必须随最终编码文件生成 QA 记录；只写"已检查"不算证据。全部检查在**交付的编码文件**上执行，从不在中间渲染上执行。

```bash
node skills/footage-led-montage/tools/render.cjs --recipe projects/<项目>/recipe.json
python3 skills/footage-led-montage/tools/qa/verify.py --recipe projects/<项目>/recipe.json
python3 skills/footage-led-montage/tools/qa/repetition.py --recipe projects/<项目>/recipe.json
```

- `qa/verify<qa_suffix>.json`：逐文件的媒体门槛（画布、帧数、帧率、编码、像素格式、faststart、音频流），`audio_identity`（各变体音轨哈希与共享混音是否一致），`plan_duplicate_ratio`（计划级重复度的 `recomputed` / `recorded` / `limit` / `passed`），以及 `status` 与 `failures`。同时输出 `qa/frame-samples<qa_suffix>.json` 与人工复核抽帧。
- `qa/final-repetition<qa_suffix>.json`：`max_pairwise_visual_duplication`（成片级）与 `limit`（计划级上限）两块，各自的 `status` 与 `failures`。
- 图形层报告（`overlay-report.json` 与 `mask-coverage.json`）：`caption_band` 推导结果与全部候选聚类、`frames` 统计、`checks`（暴露/越界/半透明/面板缺口像素数）、`status`、`failures`。
- 时间线与渲染报告（`paths.reports`）：每个片段的成片区间、源文件区间、帧数、内部场景切点数量、转场证据、偏离 3 秒节拍的理由，以及本次运行的 `recipe_sha256` 与 `runner_sha256`。
- 人工复核记录：每个边界的转场前/边界/中点/结束抽帧；未抽查的边界必须标为未验证。内容判断（口感画面、产品证据、源素材原版明暗、隐藏硬切、源字幕、水印、人物、禁用项）不能由自动检查替代。

自动检查工具不可用时将该项标为 `unverified` 并阻断通过。每个变体的 QA 文件须与视频一并交付；只有所有必检项均有证据且通过时，状态才可为 `pass`。

## 起草新配方

拿到新参考片时按 [DRAFTING.md](DRAFTING.md) 走：`tools/draft-recipe.cjs` 生成草案（测量事实 + 骨架 + 确认清单），图形层用 `tools/graphics/extract-overlay.py`，补齐后校验 schema 并锁 `runner_sha256`。画布与 `body_frames` 是交付选择而非参考片属性，必须人工确认。
